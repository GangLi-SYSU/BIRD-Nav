## 每一步的含义

1. 在当前位姿拍摄真实场景RGB，沿用最新帧、位姿/光学参数核验及连续两次MAE≤0.5/255的稳定要求。
2. 网络只读取RGB，输出机体系归巢向量，单位m。
3. 按拍照时航向转换到世界坐标；转向预测方向，移动`min(0.1+0.4×预测距离/3,2.5)`m。
4. 更新相机/机器人代理位姿，读取实际USD变换核对执行位置和航向。
5. 真值水平距离≤0.5m则记成功；否则继续，最多50步。高度不参与成功距离。

控制器不读取真实归巢向量，不根据真实距离缩短最后一步。
只检查每步落点是否进入成功圈，与原代码一致；线段经过成功圈但落点在外，不计成功，另存最小线段距离。
初始就在成功圈内的情况单独记录，不计入非平凡成功率。

## 场景与执行边界

这是原仓库风格的**离散运动学位姿闭环**，不包含四旋翼动力学、惯性、制动、悬停或降落。
场景最高表面约19.74m，40m飞行平面净空约20.26m，本轮无需APF，也不据此声称具备绕障能力。
每一步按相机足迹和5m余量检查场地边界及运动线段；越界则停止并记录`out_of_bounds`，不暗中转向。
四相机分别运行独立试验，共享渲染更新；CPU执行小网络推理，避免与Isaac争用显存。

## 运行与产物

从`visual_simulator_docker/CodeInsectInspired/`先执行：

```bash
PYTHONDONTWRITEBYTECODE=1 python3 run_navigation_experiment.py --plan-only
```

然后从仓库根目录启动硬盘上的后台容器：

```bash
bash visual_simulator_docker/run_navigation_on_disk.sh
```

产物目录：`CodeInsectInspired/runs/stage12_navigation_01/`。

- `protocol.json`、`episode_plan.json`、`frozen.json`：冻结条件、全部起点/航向、代码/场景/模型哈希。
- `progress.json`、`logs/`：当前阶段、已完成次数、成功数和活动试验步数。
- `pilot/`、`formal/`：统计及每次试验的完整轨迹；每一步保存PNG、帧凭据、预测和执行记录。
- `result_summary.md`、`formal_trajectories.png`：最终报告和全部轨迹。

中断后用同一入口恢复。已完成试验校验全部文件后复用；未完成试验的图像/日志保留，
该次试验从原起点在新attempt中重跑。相机失效属于工程中断，不把受影响的未完成试验当作导航失败。
所有源文件与旧模型保留，成功阈值和控制规则在运行过程中保持冻结。
