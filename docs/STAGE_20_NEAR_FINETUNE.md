## 固定训练与选模规则

- 两组从第589轮同一完整断点恢复模型、AdamW状态，源累计301,568次更新。
- `original_data`使用原4096张训练图；`near_supplement`使用组合5640张训练图。
- 每组50段，每段512次更新、4096张无放回抽取的训练图，共25,600次更新。
  两组共用采样代码与每段的增强/加载器种子。新增数据较多的一组每段抽取一个子集，
  不以相同epoch冒充相同计算预算。这是新的微调阶段，不宣称与旧epoch采样逐位相同。
- 网络、MSE训练损失、AdamW参数、学习率0.0005、batch8、workers4、尺度44、
  384²输入、固定圆形掩膜、先缩放后随机旋转保持一致；没有学习率衰减或早停。
- 共享448张验证图，按≤0.5m、0.5–2m、2–5m、>5m四组的米制分量MSE等权平均选模。
  同时报告全场平均MSE。原589轮模型先按新规则重评分，作为第0段候选保留。
  两组完成预算并冻结选择后，才开始导航，不用104张诊断重放或导航结果反选模型。

104张旧诊断图只在选模后重放，用于观察原点误差和航向一致性；其中原点位置现为训练位置，
这不是独立测试。18个预留位置仍未采图、未评估。

## 自动执行与结果

从`Bee-Nav/`运行：

```bash
bash visual_simulator_docker/run_near_finetune_on_disk.sh --plan-only
bash visual_simulator_docker/run_near_finetune_on_disk.sh
```

容器`bee-nav-stage20-near-finetune`，目录`CodeInsectInspired/runs/stage20_near_finetune_01/`。
入口可等待第二步采集完成，再顺序执行两组GPU微调。每段保存完整断点，退出后同命令续跑。
训练采用独立进程；随后每组先通过几何、真值返回及模型检查，再执行10m/5m各64次归巢。
控制器仍为动态步长`min(0.1+0.4×预测距离/3,2.5)`m、0.5m成功圈、最多50步。

`progress.json`记录阶段、组别、更新数或导航进度；`analysis/training_live.png`和
`analysis/navigation_<arm>_live.png`在运行中约每30秒自动更新，采用原子替换。
最终生成`result_summary.md`、配对统计和两组完整轨迹图。

用本机浏览器打开`analysis/live_results.html`可每30秒自动加载最新图片；
聊天中的旧预览不会自行刷新。

新的局部验证为0.15m隔离的同场景插值；旧留出点仍保持1m隔离。
历史589轮10m40/64、5m46/64单独列作参考；本轮原数据对照已经增加相同训练预算。
单场景、单训练种子和相关航向的结果不能当作跨场景泛化或稳定悬停验证。

回归检查在项目镜像的代码目录运行：
